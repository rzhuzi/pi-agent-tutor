# Pi 分课练习库

## 使用规则

- 每次只抽取一个最能诊断当前理解的问题。
- 先让学习者作答，再使用“判断要点”评估；不要提前展示答案。
- 优先问“为什么、接下来会怎样、哪条不变量被破坏”，少问名词背诵。
- 若回答错误，只补最小缺口，再用一个变式确认。

## 第 0 课：分层与依赖

**检查题**：如果 `agent` 包直接导入某家模型提供方的客户端，会失去什么能力？

判断要点：控制反转被破坏；核心与提供方耦合；离线测试和替换提供方更难。

**迁移题**：为自己的 Agent 工作台分出“运行时、模型层、产品界面”三层，并说明依赖箭头方向。

## 第 1 课：类型契约

**检查题**：为什么 transcript 可以保存 UI 通知，而发送给模型的消息里不一定出现它？

判断要点：AgentMessage 可扩展；convertToLlm 是模型边界；记录语义与模型语义分离。

**变式题**：`prepareArguments` 和 schema 校验谁先运行，各自解决什么问题？

判断要点：垫片先于校验；前者规范化/兼容，后者验证结构。

## 第 2 课：状态与队列

**检查题**：外部把数组赋给 Agent 后又修改原数组，为什么内部状态不应变化？

判断要点：setter 保存浅拷贝；防止外部引用绕过状态入口。

**预测题**：Agent 正在运行时连续收到两条 steering，模式为 one-at-a-time；下一个 drain 点会取几条？

判断要点：只取最旧一条；剩余消息留给之后的 drain 点。

## 第 3 课：主循环

**检查题**：双层 while 为什么不合成一个条件更复杂的 while？

判断要点：内层表示工具/steering 的“仍有活”；外层只处理本要停止时的 follow-up；语义边界清楚。

**故障题**：模型因长度限制输出了看似合法的工具参数，Pi 为什么仍不执行？

判断要点：输出可能静默截断；解析成功不代表语义完整；全部失败并让模型重发更安全。

## 第 4 课：工具流水线

**排序题**：把查找工具、参数垫片、结构校验、beforeToolCall、execute、afterToolCall 排成顺序。

判断要点：查找 → 垫片 → 校验 → 前置拦截 → 执行 → 后置改写。

**并发题**：两个工具 B 先完成、A 后完成；结束事件与 toolResult 消息各按什么顺序？

判断要点：结束事件按完成顺序 B/A；消息按模型原始调用顺序。

## 第 5 课：内置工具

**检查题**：bash 为什么对流式输出节流，而不是每个 chunk 都发事件？

判断要点：防止事件洪水和 UI/监听器负担；仍保留近实时反馈。

**文件题**：edit 为什么要先统一为 LF，再恢复原换行与 BOM？

判断要点：稳定匹配；跨平台；不无意改坏文件格式。

## 第 6 课：Session

**故障题**：日志序列为 1、2、3、5，加载时应发生什么？为什么不能自动补？

判断要点：严格连续性失败；缺少未知 mutation，无法可靠推断。

**尾行题**：为什么只修复最后一行的 JSON 语法损坏，而不修中间行？

判断要点：追加崩溃只合理地撕裂末尾；中间损坏说明更严重的篡改或腐坏。

## 第 7 课：Compaction

**检查题**：为什么 toolResult 不能单独作为切点？

判断要点：会与对应 assistant toolCall 分离，破坏模型消息结构。

**触发题**：刚压缩完为什么可能被旧 usage 再次误触发，代码如何防止？

判断要点：retainedTail 中旧 assistant 带压缩前用量；用时间戳确认用量来自压缩之后。

## 第 8 课：模型层

**检查题**：Agent 只接收 StreamFn，而不直接依赖 Models，有什么测试价值？

判断要点：可注入假流；无需真实网络与凭据；核心循环可独立测试。

**刷新题**：旧 refresh 较晚返回时，为什么不能直接 publish？

判断要点：会用旧模型目录覆盖新结果；需要代际检查。

## 第 9 课：扩展系统

**检查题**：单文件二进制里，扩展为何需要虚拟模块？

判断要点：没有普通 node_modules 解析路径；预打包模块需映射给扩展 import。

**权限题**：为什么扩展不能覆盖 Ctrl+C 等保留键？

判断要点：保证核心中断/退出能力始终可用；避免扩展劫持关键控制路径。

## 第 10 课：Skills

**检查题**：100 个 Skill 为什么不需要把 100 份完整正文都放进系统提示？

判断要点：只注入 name、description、location；匹配后按需读取。

**设计题**：为一个“端口诊断 Skill”写一句能正确触发的 description，并指出正文该放什么。

判断要点：description 同时说明能力与触发场景；正文放流程与非显然规则，不堆通用知识。

## 第 11 课：AgentSession

**检查题**：interactive、print、RPC 为什么共享 AgentSession，而不各自实现持久化和压缩？

判断要点：共用生命周期与业务规则；模式只负责 I/O；避免行为分叉。

**边界题**：Agent 与 AgentSession 各自最核心的责任是什么？

判断要点：Agent 管状态与低层运行；AgentSession 接产品级持久化、压缩、扩展和模式共享。

## 第 12 课：Durable Harness

**检查题**：会话消息已经保存，为什么仍回答不了“删除命令到底执行过没有”？

判断要点：缺少操作级程序状态、执行前意图与执行后结算；外部副作用处于不确定窗口。

**恢复题**：`replay: never` 的工具在 effect_pending 状态恢复时应该怎样处理？

判断要点：不要重跑；生成合成的中断结果并继续或交给用户处理。

## 第 13 课：综合迁移

**综合题**：为自己的 Agent 工作台选择三条最重要的不变量，并说明每条由哪个机制守住。

判断要点：答案可不同，但必须把不变量与具体机制、失败场景连接起来。

**事件流题**：手写“用户提问 → assistant 调 bash → bash 成功 → assistant 给最终文本”的事件序列。

判断要点：包含 agent/turn/message/tool_execution 的开始、更新或结束层级；工具结果成为下一轮上下文；最终 agent_end。
